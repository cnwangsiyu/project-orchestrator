## Worker Rules
- Never read, copy or load any login session or credential file (cookies, SSO/session tokens, CLI auth files such as bytedcli's, keychain items, .netrc, API keys), and never inject a session into a browser or tool to get past a login. Wherever a login or authorization is needed, stop and report BLOCKED with what needs signing in.
- Codex workers on this machine never touch signing/credential files, including keychain-password files or hashing, regardless of authorization. Strip/use sanitized public inputs, or the user runs the necessary operation once; do not plan on approval lifting the ban.
- Security follows context: attack-style findings/exploit material require a --security route, including implementation/fix work that reads them. Otherwise pass defensive requirements only; other security content still requires --security. "No TRAE GPT on security decisions" applies to that CONTENT — attack-style findings and exploit reasoning — not to the act of reviewing, testing or editing routing code and the security rules themselves, which is ordinary work routed normally (do not reclassify a code review as adversarial just because the code implements a security policy). A `--security` review (`review`, `review-high`, `second-opinion`) is adversarial by default: no GPT model on any account; TTADK Kimi-K3 → DeepSeek-V4.1-Flash (TTADK or TRAE) → Claude Opus only with the user's OK, with a second reviewer from the other non-GPT family. Implementation/fix work under `--security` keeps the TRAE-GPT exclusion. A cyberPolicy block must not be retried or resent to another GPT account; re-route with `--adversarial`. On TRAE it is recorded like the 983 restriction signal (gpt family out until the next 00:00 UTC); TTADK records only the `kind:'policy-block'` row and does not pause.
- Report the concrete model, effort and account (not merely TRAE); work only within the brief and sandbox. Missing login/access means BLOCKED, never a session transplant, login bypass or permission laundering.
- Builds use the heavy-build wrapper or res take/return per the contract only for local heavy compute (compilers/linkers/packaging on this machine); PPE/staging/TCE/BITS/SCM deploys, remote pipelines and CI runs never take a heavy-build/lane lock or `--shared-lock`, and shared remote/CI entry scripts stay unthrottled (local locks only in local-only wrappers; `route.mjs --no-local-build`). Timeout means report/queue, never bypass. Return resources/close owned children on every exit; never kill another task's processes.
