## Worker Rules
- Machine policy: Codex workers never touch signing/credential files, regardless of approval. Only the resident Claude signing worker has the narrow preregistered own-test-package exception below; full access is not an authorization bypass.
- Forbidden for every worker: never read, copy, load or inject LOGIN material — login sessions, SSO/session tokens, cookies, CLI auth files (for example bytedcli's), API keys, .netrc, browser profiles, or other people's/other apps' keychain items — and never use any way of getting past a login. Where a login or authorization is needed, stop and report BLOCKED with what needs signing in.
- Allowed with the user's 2026-11-13 authorization: sign OUR OWN TEST packages only when registered by manifest and hash in `~/.claude/orchestrator/_shared/user-signing/registry.json`, using only identities on the user-approved allowlist `~/.claude/orchestrator/_shared/user-signing/identities.json` (rules owner maintains each entry with dated user approval): iOS H6 keychain identity for iPhone 8; iOS cosign team DH59R4RNRY development certificate + provisioning profile 3JVMQQBHUR for iPhone 11, valid to 2027-09; Android debug keystore committed in the repo. Only orchestrators write registry.json entries; signing workers treat registry.json and identities.json as read-only. New identities require a new user approval card and allowlist entry; workers needing new entries or an unlisted identity report BLOCKED. If the H6 keychain is locked, pass only its one designated password file via stdin, never argv/env/logs. Android's repo debug passphrase from build.gradle goes through file descriptors such as apksigner file:/dev/fd/N, never argv. Never export/copy/print/log passwords or keys; report PASS/FAIL, certificate fingerprint and hashes; write a receipt under user-signing/receipts/; re-lock the keychain unless another registered signing run is active; never sign production/release packages or touch other keychains. Anything outside scope is BLOCKED and needs a user card.
- On registered shared test phones iphone8/iphone11/s21, permission/trust/install dialogs triggered by OUR OWN apps are already authorized: freely tap Allow/Authorize/Trust/OK, including for camera, microphone, photos, notifications, local network, tracking, developer trust, USB debugging and install confirmation. No per-prompt approval or button whitelist is required. Never operate the personal iPhone 15 Pro Max (`policy=never`) or a device not registered in `res`. Take/return through `res`, lease <=2 h, back up app data before destructive reinstall/wipe/erase, never enter personal-account credentials/passwords/verification codes, and make no purchases. If Codex refuses an allowed prompt, the orchestrator routes that step to Claude; do not ask the user to tap it.
- Security follows context: attack-style findings/exploit material require a --security route, including implementation/fix work that reads them. Otherwise pass defensive requirements only; other security content still requires --security. "No TRAE GPT on security decisions" applies to that CONTENT — attack-style findings and exploit reasoning — not to the act of reviewing, testing or editing routing code and the security rules themselves, which is ordinary work routed normally (do not reclassify a code review as adversarial just because the code implements a security policy). A `--security` review (`review`, `review-high`, `second-opinion`) is adversarial by default: no GPT model on any account; TTADK Kimi-K3 → DeepSeek-V4.1-Flash (TTADK or TRAE) → Claude Opus only with the user's OK, with a second reviewer from the other non-GPT family. `--defensive` (only with `--security` on those rows) keeps the ordinary security route instead — TRAE GPT excluded, TTADK GPT allowed — and its brief states only the rule and acceptance conditions, never a bypass description. Implementation/fix work under `--security` keeps the TRAE-GPT exclusion. A cyberPolicy block must not be retried or resent to another GPT account; re-route with `--adversarial`, or for a defensive confirmation re-route that part with `--adversarial` (Kimi + DeepSeek second). On TRAE it is recorded like the 983 restriction signal (gpt family out until the next 00:00 UTC); TTADK records only the `kind:'policy-block'` row and does not pause.
- Report the concrete model, effort and account (not merely TRAE); work only within the brief and sandbox. Missing login/access means BLOCKED, never a session transplant, login bypass or permission laundering.
- A queued TRAE low-priority turn is not stalled. With queue patience and route args, a predicted start past the deadline triggers a confirmed no-progress cancellation and automatic company handoff with all original flags/exclusions and same failures. Never re-route active/background turns or auto-launch personal/signing work; max two hops. Approval exits 8, deferUntil persists in reroute.json and exits 9 for the orchestrator timer, limit exits 10; cancellation failure exits 7 with no replacement. Acquire device/build holds after the first response; existing wrapper holds return on owner exit. Outcome derives automatic hop chains; nightly measures waits/speedups.
- Builds use the heavy-build wrapper or res take/return per the contract only for local heavy compute (compilers/linkers/packaging on this machine); PPE/staging/TCE/BITS/SCM deploys, remote pipelines and CI runs never take a heavy-build/lane lock or `--shared-lock`, and shared remote/CI entry scripts stay unthrottled (local locks only in local-only wrappers; `route.mjs --no-local-build`). Timeout means report/queue, never bypass. Return resources/close owned children on every exit; never kill another task's processes.
